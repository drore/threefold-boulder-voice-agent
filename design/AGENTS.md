# Interface concept instructions

This folder holds reviewable visual proposals and generation prompts. Inherit [root engineering instructions](../AGENTS.md); these assets do not authorize application implementation or change accepted product behavior.

- [SPEC](../SPEC.md) owns scope/status; [voice and UI contracts](../spec/spec-design-voice.md) and [workflow](../spec/spec-process-workflow.md) own behavior. Keep mockups consistent with current confirmation, policy, source, and action-outcome rules.
- Label proposals and synthetic scenario data clearly. No generated screenshot, fictional receipt, or hours badge is evidence of an actual provider call, live city status, deployed interface, accessibility conformance, or real municipal response.
- Keep prompts and selected outputs together. Preserve useful versions; update links and proposal status after review. Generated visual wording is illustrative until reviewed and placed in the appropriate message/prompt/configuration source.
- Review legibility, wide/narrow responsive hierarchy, confirmation details, demo labels, source links, and truthful pending/failure/uncertain/success states. Verify relative links, asset existence, and whitespace; application/browser checks are future implementation work.
- Add a local `AGENTS.md` if a maintained subfolder is introduced. Do not add runtime credentials, real caller data, or application code here.
